# Features

This is the list of what must still be in the game. Each line is one behavior a player can see or trigger, with the file that owns it.

Rules:
- Every PR that adds or changes a feature updates this file in the same PR, ending the line with its issue `(#N)`.
- Never delete a line unless an issue asks for that feature to go. In that case move it to **Removed on purpose** and name the issue.
- The `id` in front of each line is stable. A test's title starts with the exact id of the line it guards (e.g. `it('presence.lunch: …', …)`, several ids joined with ` + `), so `grep` finds it. Name the test file after the path (`test:` for Vitest, `e2e:` for Playwright).
- `url:` is where a dev sees the line in the running app: a path for the dev server, without host and port (`/?seed=1&time=11&event=coffee`). Use `?seed=1&time=…` for a repeatable start and `?event=<dev event id>` (`dev.list()` in the console) for a state the sim only reaches by chance; register a dev event if none fits. `?seed` starts like a fresh browser profile: nothing saved in `localStorage` is read or written (one exception: a dismissed welcome card stays dismissed), so the URL shows the same world on every port (#124). Add one to every line you add or change where a URL can show it. `e2e/feature-urls.spec.ts` opens each of them.
